2. PHONE/SMS OTP

   * User enters phone number.
   * Clerk sends SMS verification code.
   * User enters OTP.
   * Complete the Clerk sign-in/session.
   * Use the resulting Clerk session for API authentication.
   * Do not implement a custom OTP system.
   * Do not store OTP codes.
   * Do not build a second authentication system.

3. MFA

   * Keep the existing Clerk MFA flow unchanged.
   * Do not refactor MFA as part of this task.

4. PASSWORD RECOVERY

   * Keep the existing Supabase-owned password recovery implementation unchanged.
   * Do not route password recovery through Clerk.

5. BIOMETRIC / DEVICE UNLOCK

   * Keep the existing biometric/device-unlock behavior unchanged.
   * It must remain a local gate over the authenticated provider session.
   * Do not replace it with a new biometric implementation.

6. API

   * Keep TRAVEL_LAND_API_AUTH_PROVIDER=dual.
   * Clerk tokens must continue to work.
   * Supabase tokens must continue to work.
   * Do not change the identity mapping architecture.
   * Clerk identity continues to resolve through users.clerk_user_id.
   * Supabase identity continues to resolve only through users.auth_user_id.
