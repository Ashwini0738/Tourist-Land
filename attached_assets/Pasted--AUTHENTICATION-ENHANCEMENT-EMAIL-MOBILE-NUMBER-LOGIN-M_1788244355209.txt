# AUTHENTICATION ENHANCEMENT — EMAIL + MOBILE NUMBER LOGIN

Modify the existing Travel & Land authentication system to support BOTH:

1. Email authentication
2. Mobile number authentication

Do NOT replace the existing authentication architecture.

The application currently uses Clerk.

Use Clerk as the single source of truth for authentication, verification, sessions, and user identity.

Do NOT create a separate custom authentication database or duplicate authentication system.

---

# 1. REQUIRED LOGIN OPTIONS

On the initial authentication screen, provide two clear options:

📧 Continue with Email

📱 Continue with Mobile Number

The design should be premium, attractive, and consistent with the existing Travel & Land visual design.

Allow the user to switch between the two methods easily.

---

# 2. NEW USER REGISTRATION

For a new user, support:

## Email registration

User enters:

Email

↓

Email OTP

↓

Verify OTP

↓

Create/complete Clerk account

OR

## Mobile registration

User enters:

Country

Mobile number

↓

SMS OTP

↓

Verify OTP

↓

Create/complete Clerk account

Do not require the user to register using both email AND mobile number unless Clerk configuration/business rules require it.

The user should be able to choose either authentication method.

---

# 3. RETURNING USER LOGIN

If the user has already completed authentication and enabled device authentication:

Open app

↓

Fingerprint / Face ID / Device Lock

↓

Restore existing authenticated Clerk session

↓

Home

Do NOT show:

Email OTP

Mobile OTP

Email/password

PIN creation

on every app launch.

This is extremely important.

---

# 4. FALLBACK AUTHENTICATION

If biometric/device authentication is unavailable or the user chooses another login method:

Allow:

Email → OTP

OR

Mobile → OTP

Then restore the existing Clerk session.

Do not force biometric enrollment again if it was already configured.

---

# 5. DEVICE AUTHENTICATION

After the FIRST successful email or mobile verification:

Offer:

"Secure your account"

Options:

✓ Fingerprint

✓ Face ID

✓ Device Lock / Passcode

Use the existing secure device authentication implementation.

Do NOT store biometric information.

Do NOT create a second application-specific PIN.

The phone's native device lock/biometric system should remain the security mechanism.

---

# 10. OTP SECURITY

Use Clerk's verification mechanisms.

Do NOT:

* Store OTPs
* Generate OTPs locally
* Log OTPs
* Store OTPs in AsyncStorage
* Store OTPs in application state longer than necessary
* Create a custom SMS authentication backend

Respect Clerk's verification and resend limits.
