Implement the **post-authentication navigation flow fix only** for the Tourism app.

### Goal

After successful authentication, the app must NOT directly force the user to Home before the device-security state has been evaluated.

The required flow is:

**Email/password login**
`Login → Clerk sign-in → finalize session → root auth/security routing → biometric setup OR biometric unlock → role resolution → correct Home`

**Email verification**
`Email verification → signUp.finalize() → root auth/security routing → biometric setup OR biometric unlock → role resolution → correct Home`

For a first-time authenticated user:

`Successful authentication → /biometric → Enable/Skip → /(tabs)`

For an existing user with biometric/device security enabled:

`Successful authentication → /biometric-login → successful unlock → /(tabs)`

For an existing user with device security disabled:

`Successful authentication → /(tabs)`

For SecureStore failure:

`Successful authentication → SECURE_STORAGE_UNAVAILABLE recovery state`
and **never directly to Home**.
