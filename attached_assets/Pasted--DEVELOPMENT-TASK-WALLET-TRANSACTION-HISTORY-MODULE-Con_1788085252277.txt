---

# 5. LEDGER PRINCIPLE

The transaction ledger should be authoritative.

Every wallet balance-changing operation must create a corresponding transaction.

Do not silently modify the balance without a ledger entry.

Prefer an immutable transaction history.

Do not allow users to edit or delete transactions.

---

# 6. BALANCE CONSISTENCY

Balance changes must be atomic.

For a debit:

1. Verify wallet ownership.
2. Verify sufficient balance.
3. Create transaction.
4. Update wallet balance.
5. Commit transaction.

For a credit:

1. Verify source.
2. Create transaction.
3. Update wallet balance.
4. Commit transaction.

Use database transactions.

Never allow:

* Negative balance unless explicitly supported
* Partial wallet updates
* Duplicate credits
* Duplicate debits
