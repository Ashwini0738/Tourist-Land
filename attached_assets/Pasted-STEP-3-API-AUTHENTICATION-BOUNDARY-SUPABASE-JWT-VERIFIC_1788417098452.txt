OBJECTIVE:

Prepare the Express API so it has a clean provider-neutral authentication boundary and can safely support Supabase JWT verification later.

CURRENT FLOW:

Bearer token
→ Clerk Express middleware
→ getAuth(req)
→ Clerk user ID
→ users.clerk_user_id
→ local users.id
→ existing authorization

FUTURE FLOW:

Bearer token
→ Supabase JWT verification
→ verified Supabase subject (`sub`)
→ users.auth_user_id
→ local users.id
→ existing authorization

The existing local user/role/ownership system must remain unchanged.

IMPORTANT IDENTITY RULE:

Never replace `users.id` with the Supabase user ID.

Never use the Supabase `sub` directly as application ownership.

Always resolve:

Supabase `sub`
→ users.auth_user_id
→ users.id

`users.auth_user_id = verified sub`
