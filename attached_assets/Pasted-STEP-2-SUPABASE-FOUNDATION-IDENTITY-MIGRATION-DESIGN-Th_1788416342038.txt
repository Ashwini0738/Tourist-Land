OBJECTIVE:

IDENTITY ARCHITECTURE:

The existing local application user UUID must remain authoritative for application ownership.

Do NOT replace:

users.id

with a Supabase Auth user ID.

Instead introduce an explicit external-auth mapping.

Preferred design:

users.id
↓
users.auth_user_id
↓
Supabase auth.users.id

The new field must be designed so that:

* it can reference a Supabase Auth user ID
* it is nullable during migration
* it is unique
* existing users remain untouched
* existing foreign keys continue using users.id
* existing bookings/favorites/reviews/wallet/etc. do not need to change their ownership IDs

If the existing schema makes a different provider-neutral design safer, explain it before implementing it.
