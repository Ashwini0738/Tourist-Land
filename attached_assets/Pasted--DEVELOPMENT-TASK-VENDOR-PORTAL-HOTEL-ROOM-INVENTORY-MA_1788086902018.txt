# OBJECTIVE

Build the **Vendor Portal** for hotel/accommodation vendors.

A vendor should be able to securely manage their own:

* Hotel listings
* Hotel information
* Rooms
* Room pricing
* Room inventory
* Availability
* Blackout dates
* Booking visibility
* Property status

The vendor must NEVER be able to manage another vendor's data.

---

# 1. VENDOR DASHBOARD

Create a dedicated Vendor Dashboard.

The dashboard should show:

### Overview

* Total properties
* Active properties
* Total rooms
* Today's bookings
* Upcoming bookings
* Pending actions

### Quick actions

* Add Hotel
* Manage Hotels
* Manage Rooms
* Manage Availability
* View Bookings

Do not display fake statistics.

If there is no data:

Show:

"0 properties"

"0 bookings"

etc.

# 3. VENDOR ROLE PROTECTION

All vendor routes must be protected.

Only:

role = vendor

can access Vendor Portal screens.

If:

user → Vendor Portal

show:

"Vendor access required"

and redirect safely.

If:

admin → Vendor Portal

do not automatically treat admin as vendor.

Maintain strict role separation.

# 13. INVENTORY MANAGEMENT

Create:

Vendor
→ Availability

Vendor should be able to manage room inventory by date.

Display:

* Date
* Room type
* Total inventory
* Available inventory
* Reserved inventory

Example:

Deluxe Room

30 Aug

Total: 10

Available: 7

Reserved: 3

Do not allow available inventory to exceed total inventory.

---

# 14. INVENTORY UPDATE

Allow vendors to update:

* Total room units
* Availability
* Closed dates

All updates must be server validated.

Do not allow vendors to reduce inventory below already-reserved rooms.

Example:

Total rooms = 10

Reserved = 8

Vendor cannot change total inventory to 5.

Show a clear error.

---

# 15. BLACKOUT DATES

Allow vendors to mark dates as unavailable.

Example:

Hotel closed:

25 Dec – 27 Dec

Those dates should not appear as available to travellers.

Do not modify existing confirmed bookings automatically.

---

# 16. AVAILABILITY INTEGRATION

The existing traveller Availability API must use vendor-managed inventory.

Replace seeded availability where the vendor's real inventory exists.

Flow:

Vendor updates inventory

→ Server stores inventory

→ Traveller checks availability

→ Traveller sees current inventory

Do not break existing development inventory if no vendor inventory exists.

---

# 17. PRICE INTEGRATION

The existing traveller Availability API must use vendor-managed room prices.

Flow:

Vendor updates price

→ Availability API

→ Traveller sees updated price

Do not allow the mobile client to override vendor price.

# 25. OWNERSHIP SECURITY

Every vendor API must verify:

Authenticated user

→ vendor role

→ vendor identity

→ resource ownership

Example:

Vendor A requests:

GET /api/v1/vendor/hotels/vendor-B-hotel

Server must return:

403 Forbidden

or:

404 Not Found

Do not leak whether another vendor owns the resource.
