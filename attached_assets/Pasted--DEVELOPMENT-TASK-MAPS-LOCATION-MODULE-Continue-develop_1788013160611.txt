Continue development of the existing **Travel & Land** application.

## IMPORTANT — COMPLETED MODULES

Treat these as stable:

* User authentication
* Vendor authentication
* Admin authentication
* Clerk authentication
* Email verification / OTP / MFA
* Fingerprint / Face ID / native device authentication
* Role-based authorization
* User Home
* Explore
* Search
* Explore filters and sorting
* Destination Details
* Existing API architecture
* OpenAPI specification
* Generated TypeScript API client
* Generated React Query hooks
* Generated Zod schemas

Do NOT rebuild or modify authentication, roles, Home, Explore, or Destination Details.

---

# OBJECTIVE

Build the **Maps + Location module** for Travel & Land.

The module should allow users to:

* View destinations on a map
* View tourist places
* View temples
* View attractions
* View hotels
* View properties/land opportunities
* See their current location when permission is granted
* Search/select a location
* View markers
* Open location details
* Navigate from map markers to details
* Request directions when supported

The implementation must support:

* Android
* iOS
* Expo Go
* Mobile web

---

# 1. MAP SCREEN

Create a dedicated Maps screen.

The screen should contain:

* Full-screen map area
* Back button
* Search/location field
* Current-location button
* Category/filter controls
* Map markers
* Bottom result preview/list

Use the existing Travel & Land design system.

Keep the interface mobile-first.

---

# 2. MAP PROVIDER

First inspect the existing project to determine whether a map provider is already configured.

If a provider already exists:

* Reuse it.
* Do not replace it.

If no provider exists:

Choose an architecture that can support:

* Android
* iOS
* Web

Do NOT add a paid provider requiring a production API key without documenting the requirement.

Do NOT hardcode API keys into source code.

Use environment variables for provider credentials.

---

# 3. CURRENT LOCATION

Implement current location functionality.

When the user taps:

"Use my location"

request location permission.

Do NOT automatically request location permission simply because the Maps screen opened unless the existing UX explicitly requires it.

Handle:

* Permission granted
* Permission denied
* Permission permanently denied
* Location unavailable
* GPS disabled
* Loading location

If permission is denied, the map must still work.

Allow the user to manually search/select a location.

---

# 4. LOCATION DISPLAY

When permission is granted:

Display:

* Current position
* Location marker
* Optional accuracy indicator

Do not continuously track GPS unless required.

Avoid unnecessary battery usage.

Use a one-time location lookup initially.

---

# 5. REVERSE GEOCODING

→ Country

Reuse the existing location/reverse-geocoding architecture if already implemented.

Do not create duplicate location services.

# 21. LOCATION PERMISSIONS

Handle all states gracefully.

### Granted

Show current location functionality.

### Denied

"Location permission is disabled"

or manual location search.

### Unavailable

Allow manual location selection.

Do not repeatedly trigger permission prompts.
